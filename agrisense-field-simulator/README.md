# AGRI-SENSE: Intelligent Agricultural Field Digital Twin

## Project Overview
This project is a digital twin for an agricultural field, serving as Laptop 1 in the AGRI-SENSE ecosystem. It simulates a field with 4 zones and 12 moisture sensors, allowing for the injection of various faults (outliers, stuck sensors, drift, missing sensors, noise, bias). 

The primary goal of this application is to **simulate conditions** and **generate observations**, while relying entirely on an external ESP32 microcontroller for all **intelligence and decision making**.

## Responsibility Boundaries

### Laptop 1 (This Project)
- **Simulation**: Generates realistic ground truth and observed moisture values based on environmental factors (rainfall, temperature, flow).
- **Fault Injection**: Allows users to explicitly inject scenarios (faults) to test the ESP32's anomaly detection capabilities. 
- **Packet Generation**: Produces a JSON packet containing ONLY the raw observations.
- **USB Serial Transmission**: Transmits the JSON packet to the ESP32 over a wired USB Serial connection.
- **Important**: Laptop 1 **NEVER** includes fault labels in the packet, and **NEVER** calculates state estimation, confidence, or irrigation decisions.

### ESP32 (External Microcontroller)
- **Intelligence layer**: Receives the raw JSON packet via UART.
- **Validation & Fault Detection**: Analyzes the raw data to discover the faults injected by Laptop 1.
- **Decision Making**: Estimates true moisture, calculates confidence, and decides whether to trigger irrigation.
- **Wireless Transmission**: Transmits the processed intelligence results over Wi-Fi to Laptop 2.

### Laptop 2 (External Dashboard)
- **Visualization**: Exclusively visualizes the final intelligence and decisions generated by the ESP32.

## Architecture & Transport
```text
React Frontend (UI)
      ↓
Python FastAPI (Simulation Engine)
      ↓
USB Serial (Wired connection)
      ↓
ESP32 (Intelligence)
      ↓
Wi-Fi (Wireless connection)
      ↓
Laptop 2 (Dashboard)
```

## Serial Configuration
By default, the backend attempts to connect on `COM5` at `115200` baud. This can be configured at runtime via the API.
Packets are sent as **newline-delimited JSON**.

## Setup & Running
**Backend (Python FastAPI)**
```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**Frontend (Next.js)**
```bash
cd nextjs
npm install
npm run dev
```
