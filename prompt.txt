# AGRI-SENSE — CRITICAL COMMUNICATION ARCHITECTURE UPDATE

IMPORTANT:

Update the existing AGRI-SENSE implementation plan.

Do NOT rebuild the project from scratch.

The previous implementation plan assumed Python would communicate with the ESP32 over Wi-Fi/HTTP.

THAT IS NO LONGER THE ARCHITECTURE.

The final communication architecture is:

LAPTOP 1 → WIRED USB SERIAL → ESP32 → WIRELESS WI-FI → LAPTOP 2

Python remains the backbone of Laptop 1.

React remains the frontend of Laptop 1.

ESP32 performs the intelligence.

Laptop 2 receives the processed ESP32 result wirelessly.

============================================================
6. SERIAL COMMUNICATION
============================================================

Python FastAPI must communicate with ESP32 through USB serial.

Example:

COM5

Baud:

115200

However:

DO NOT hard-code COM5.

The serial configuration must be changeable.

Configuration:

SERIAL_PORT=COM5
SERIAL_BAUDRATE=115200
SERIAL_TIMEOUT=2

These should be defaults only.

============================================================
7. SERIAL CONFIGURATION API
============================================================

Add:

POST /api/serial/config

Example:

{
    "port": "COM5",
    "baudrate": 115200,
    "timeout": 2
}

Also add:

GET /api/serial/status

Return:

{
    "status": "CONNECTED",
    "port": "COM5",
    "baudrate": 115200,
    "last_error": null
}

Possible states:

DISCONNECTED
CONNECTING
CONNECTED
ERROR
TIMEOUT

============================================================
8. SERIAL SEND API
============================================================

Add:

POST /api/esp32/send

The behavior must now be:

1. Get current simulation state.
2. Generate canonical packet.
3. Serialize packet to JSON.
4. Add a newline delimiter.
5. Send JSON over USB serial.
6. Log transmission.
7. Return transmission status.

Example transmitted serial line:

{"timestamp":125,"rainfall_mm":0,"zones":[...]}

followed by:

\n

The ESP32 should therefore be able to read one complete packet at a time.

============================================================
9. SERIAL PACKET FRAMING
============================================================

Use newline-delimited JSON.

Every packet sent from Python to ESP32 must be:

ONE JSON OBJECT

followed by:

NEWLINE

Example:

{
    "timestamp": 125,
    "rainfall_mm": 0,
    "zones": [...]
}\n

This provides a simple packet boundary.

Do not send arbitrary Python repr() output.

Do not send:

str(dictionary)

Use valid JSON serialization.

============================================================
15. ARDUINO SERIAL MONITOR WARNING
============================================================

IMPORTANT:

Do NOT assume Python and Arduino IDE can simultaneously open the same COM port.

If Python owns:

COM5

Arduino IDE's Serial Monitor generally cannot also open COM5 at the same time.

Therefore support two development modes.

MODE A:

Python owns COM5.

Arduino IDE Serial Monitor is closed.

This is the normal integrated operation.

MODE B:

Stop Python serial communication.

Open Arduino IDE Serial Monitor.

Use it to inspect ESP32 debug output.
